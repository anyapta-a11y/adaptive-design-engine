# Архитектура ADE — прототип v0 (библиотека слайдов)

Статус: прототип по концепции Анны от 2026-10-14 (D-005). Не финальная архитектура.

## Идея
Своя библиотека частых слайдов, размеченная один раз → skill выбирает слайды под контент Word → детерминированная программа собирает редактируемый PPTX → автоматическая проверка.

```
Word (.docx) ──► [skill: Claude] ──► plan.json ──► [ade build: Python] ──► out.pptx + out.pdf + qa.json
                    ▲ читает catalog.json                ▲ library.pptx
```

Разделение ответственности:
- **Claude (skill)** — понимание смысла: делит документ на блоки, выбирает семейство слайда, раскладывает текст по полям. Не переписывает и не сокращает текст клиента.
- **Программа (`ade`)** — всё, что должно быть одинаково каждый раз: выбор варианта по числу элементов, клонирование, заполнение, таблицы, диаграммы, подгонка текста, QA.

## 1. Библиотека (`library.pptx`)
Обычный PPTX, который дизайнер правит в PowerPoint. Разметка — двумя способами, оба видны и правятся в PowerPoint:

**Заметки слайда** (первая строка, формат `ade:` + key=value через `;`):
```
ade: id=cards-3; family=cards; purpose=Три параллельных преимущества/тезиса с коротким пояснением
```
- `id` — уникальный; `family` — семейство вариантов (`cards`, `process`, `kpi`, `table`, `chart`, `text`, `title`); `purpose` — для выбора skill'ом.

**Имена фигур** (Selection Pane в PowerPoint):
| Имя | Роль |
|---|---|
| `title`, `subtitle`, `body`, `note` | Текстовые слоты |
| `item[1]`, `item[2]` … | Повторяемый элемент (группа или фигура); номер = порядок |
| `item[1].title`, `item[1].body`, `item[1].value`, `item[1].label`, `item[1].num` | Поля внутри элемента (дети группы) |
| `connector[1]` … | Соединитель между item[i] и item[i+1] |
| `table` | Нативная таблица; строка 1 — шапка |
| `chart` | Нативная диаграмма |
Фигуры без имени по этой схеме — декор, не трогаются.

Вариант семейства = отдельный слайд, сверстанный дизайнером (`cards-2`, `cards-3`, `cards-4`…). Число элементов варианта = число `item[n]`.

## 2. Каталог (`ade catalog library.pptx > catalog.json`)
Генерируется из разметки, не пишется руками. На слайд: `id, family, purpose, slots[], item_count, item_fields[], table{cols, rows}, chart{type, series, categories}`, плюс оценка вместимости текста каждого слота в символах (по метрикам шрифта). Ошибки разметки (дубль id, пропуск номера item) — явная ошибка.

## 3. План (`plan.json`) — контракт skill → программа
```json
{"slides": [
  {"family": "cards", "fields": {"title": "…"},
   "items": [{"title": "…", "body": "…"}, …]},
  {"id": "table-std", "fields": {"title": "…"},
   "table": [["Регион","Выручка"],["А","100"], …]},
  {"family": "chart", "fields": {"title": "…"},
   "chart": {"categories": ["A","B"], "series": [{"name": "2026", "values": [1,2]}]}}
]}
```
Указывается `id` (конкретный слайд) или `family` (программа выберет вариант).

## 4. Сборка (`ade build --library L --plan P --out O`)
Для каждого слайда плана:
1. **Выбор варианта**: точное совпадение `item_count`; иначе ближайший меньший вариант + клонирование `item[last]` (с перенумерацией `cNvPr id` и `connector`) и перераспределение в пролёте; если элементов меньше — ближайший больший вариант + удаление лишних с перераспределением.
2. **Копирование слайда** из библиотеки в результат с глубоким копированием частей диаграмм (chart part + встроенный xlsx), картинок по связям.
3. **Заполнение**: текст в первый run с сохранением форматирования; таблица ±строки клонированием `a:tr` с сохранением чередования, при переполнении высоты — сжатие строк до минимума, дальше — предупреждение; диаграмма через `replace_data` с явным `number_format` и цветами серий.
4. **Подгонка текста**: метрики шрифта (Pillow, шрифты из `fonts/` или системные). Порядок: (а) кегль вниз шагом 1pt, не ниже 75% исходного, единый для однотипных полей на слайде; (б) если не влезает — предупреждение, текст не сокращается.
5. Выходные слайды в порядке плана; слайды библиотеки в результат не попадают.

## 5. QA (`ade qa O`) → `qa.json`
FAIL: дубли `cNvPr id`; картинки вместо нативных объектов, которых не было в библиотеке; выход за слайд; наложение элементов item; разрыв слова; текст не помещается; потеря контента (каждая строка плана присутствует в файле 1:1); пустые слоты из плана.
WARN: кегль уменьшен; клонирование вместо готового варианта.
Плюс рендер в PDF/PNG через LibreOffice (визуальная проверка — дополнение, не замена).

## 6. Skill (`.claude/skills/ade-build/SKILL.md`)
1. Прочитать DOCX (python-docx → текст с заголовками, списками, таблицами).
2. Прочитать `catalog.json` (не library.pptx).
3. Составить `plan.json`: каждый блок → семейство по `purpose`; текст дословно.
4. `ade build` → `ade qa`; при FAIL — исправить план (другой вариант/разбить блок на два слайда) и повторить, максимум 2 раза.
5. Отдать PPTX, PDF и краткий отчёт QA.

## Структура кода
```
ade/
  catalog.py   # разметка → catalog.json
  build.py     # plan + library → pptx
  ops/         # slides.py (копирование), repeat.py, table.py, chart.py, text.py
  qa.py
  cli.py       # ade catalog | build | qa
tests/          # pytest на синтетической библиотеке
examples/       # make_library.py (синтетическая библиотека), sample plan, sample docx
```
Ядро не зависит от формата только на уровне плана и каталога (контракт); отдельный слой IDM не вводим до второй платформы (D-005).
