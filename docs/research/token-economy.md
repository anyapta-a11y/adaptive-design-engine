## 1. Статья vitalyvlada.ru: что утверждается

- Связка «Graphify + Obsidian + obsidian-skills»: Graphify один раз читает проект и строит граф связей,
  Claude отвечает по карте, а не перечитывает файлы. Obsidian хранит «не-код» (бизнес-контекст),
  Graphify может выгружать карту в хранилище Obsidian. **[заявление]**
- Цифры: «экономия токенов до 71 раза»; «один вопрос стоил 123 000 токенов без карты и около 1 700 с
  картой» (≈72×); «независимые тесты показывают экономию от 7 до 49 раз». **[заявление]**
- Измерения: один замер на проекте из 52 файлов. Не указаны вопрос, модель, способ подсчёта, число
  прогонов и разброс. Ссылок на «независимые тесты» нет. **[точно]** (по тексту статьи)
- Совпадение с README Graphify: в docs/how-it-works.md приведён пример «52 files: 71.5x fewer tokens»
  на корпусе Karpathy repos + 5 статей + 4 картинки. Цифра статьи почти наверняка повторяет этот пример
  или его воспроизведение, а не независимое измерение. **[вероятно]**
- Статья заканчивается предзаписью на платный курс через Telegram-бот, то есть это маркетинговый
  материал. **[точно]**

## 2. Graphify: разбор по исходникам

### 2.1 Паспорт
| Параметр | Значение | Метка |
|---|---|---|
| Лицензия | Apache-2.0; части, внесённые раньше, остаются под MIT (LICENSE-MIT, NOTICE) | точно |
| Пакет | `graphifyy` 0.9.90, Python ≥3.10 | точно |
| Активность | много коммитов в день (последний 2026-10-13), 2380 коммитов, 674 открытых issue | точно |
| Популярность | ≈126k звёзд, 12.2k форков (страница GitHub через WebFetch) | вероятно (не через API) |
| Владелец | Graphify Labs (YC S26), есть платный Graphify Cloud с триалом | точно |
| Зависимости ядра | networkx, numpy, rapidfuzz, tree-sitter 0.25 и около 27 пакетов грамматик | точно |
| Опции | mcp, neo4j, pdf, video (faster-whisper, yt-dlp), LLM-бэкенды (openai, anthropic, gemini, bedrock…) | точно |

### 2.2 Как строится граф и сколько стоит построение
- **Код** разбирается локально через tree-sitter AST (около 40 языков). Связи `calls`, `imports`,
  `inherits` разрешаются между файлами. Сообщества строятся алгоритмом Leiden или запасным. **LLM не
  вызывается, 0 токенов.** Проверено по skill.md: для корпуса только из кода «skip Part B entirely».
  **[точно]**
- **Документы, PDF, картинки** проходят семантический этап через LLM. Вариант по умолчанию: хост-агент
  (Claude Code) запускает **параллельных субагентов** через Agent tool, и это тратит токены сессии.
  Второй вариант: Gemini, если задан `GEMINI_API_KEY`/`GOOGLE_API_KEY`. В headless-режиме
  `graphify extract` сам выбирает провайдера по найденному ключу: Gemini → Kimi → Claude → OpenAI → …
  **[точно]**
- Для ADE (Python и немного markdown) это значит: код бесплатен. Markdown в репозитории без
  `--code-only` попадёт в семантический этап, и субагенты потратят токены. Объём зависит от количества
  документов. **[гипотеза]**: несколько тысяч токенов на файл, не измерялось.
- **Скрытая стоимость в контексте.** Сам skill `graphify/skill.md` занимает около 46 КБ (≈11–12k
  токенов), и он загружается в контекст при каждом вызове `/graphify`. Блок always-on для CLAUDE.md весит
  около 1.2 КБ (≈300 токенов в каждой сессии). **[точно]** по размеру файлов, токены оценены как
  символы/4.

### 2.3 Где хранится граф
- `graphify-out/graph.json` (полный граф), `GRAPH_REPORT.md` (сводка), `graph.html` (визуализация). **[точно]**
- Размеры: пример на 52 файла даёт graph.json 120 КБ и отчёт 17 КБ (`worked/karpathy-repos`). Для ERPNext
  (около 3.7k файлов) граф содержит 22k узлов и 48k рёбер, то есть файл весит мегабайты. **[точно]**/**[вероятно]**
- Коммит графа в репозиторий поддерживается («Team setup»). Для `graph.json` регистрируется git
  merge driver, который объединяет версии при слиянии (`.gitattributes: graphify-out/graph.json merge=graphify`). **[точно]**

### 2.4 Интеграция с Claude Code
- **Skill**: `graphify install [--project]` пишет `.claude/skills/graphify/SKILL.md` и `references/`. **[точно]**
- **Hook**: PreToolUse на `Bash|Grep` и `Read|Glob` вызывает `graphify hook-guard` (около 170 мс, тайм-аут
  10 с) и подталкивает агента к запросам в граф. Режим `--strict` **блокирует первое прямое чтение
  файла в сессии**. **[точно]** (install.py)
- **Git hooks**: post-commit, post-checkout и post-merge пересобирают граф; плюс merge driver. **[точно]** (hooks.py)
- **MCP**: опциональный `graphify-mcp` (stdio или HTTP, extra `mcp`). **[точно]**
- **CLI-запросы**: `graphify query "<вопрос>" --budget N`, `path A B`, `explain X`. Бюджет ответа по
  умолчанию около 2000 токенов. **[точно]**

### 2.5 Безопасность и приватность
- Анализ только кода работает офлайн. Телеметрии в коде не нашёл, README прямо пишет «No telemetry».
  **[вероятно]**: прочитаны не все модули.
- Внешние URL в коде: API LLM-провайдеров (используются только при наличии ключа), arxiv и fetch по URL
  для `graphify add` (с SSRF-защитой в security.py), CDN d3/jsdelivr в graph.html, а также
  `app.graphify.com`, который **только печатается** как реклама Cloud после сборки. **[точно]** (grep)
- Журнал запросов пишется в `~/.cache/graphify-queries.log` (вопросы и результаты). **[точно]**
- Риски: (а) установка меняет настройки Claude Code и `.git/hooks`; (б) очень частые релизы, поэтому
  версию нужно фиксировать; (в) если в окружении есть `GEMINI_API_KEY` или другой ключ, тексты
  документов **уходят провайдеру** автоматически; (г) инструкции skill.md агрессивные («MUST use the
  Agent tool … Reading files yourself is forbidden») и могут конфликтовать с правилами проекта. **[точно]**

### 2.6 Что на самом деле измерено (ключевой вывод)
- **«71.5×» не является замером работы агента.** `graphify/benchmark.py` считает так:
  `corpus_tokens = слова_всего_корпуса × 100/75` делится на средний размер подграфа, который вернёт
  `query_graph` при бюджете 2000 токенов. Базой сравнения служит «вставить в контекст весь корпус
  целиком», а не реальный агент с grep и Read. Поэтому отношение растёт пропорционально размеру
  корпуса почти по определению. **[точно]** (код benchmark.py)
- Сами авторы в docs/how-it-works.md пишут: 6 файлов дают около 1×, 4 файла дают 5.4×, 52 файла дают 71.5×. **[точно]**
- Наиболее честный тест в BENCHMARKS.md (ERPNext, около 1M LOC, n=6 вопросов): полнота ключевых фактов
  выросла с 70.8% (база grep/read) до 82.0% **при ≈140K токенов на запрос**. Экономия токенов против
  grep/read **не заявлена**; сравнение «в 20 раз дешевле» сделано против набивки всего репозитория в
  контекст. **[точно]**
- «80% fewer tokens» относится к платному Cloud и не подкреплено данными в репозитории. **[заявление]**
- Итог: доказанной экономии против нормального агентного поиска (rg/Glob/Read) **нет**. Есть умеренный
  прирост качества на очень большом репозитории (n=6, малая выборка).

## 3. kepano/obsidian-skills

- Что это: набор Agent Skills по открытой спецификации agentskills.io для Claude Code, Codex и OpenCode.
  Лицензия MIT, автор Steph Ango (CEO Obsidian), около 49.5k звёзд, 49 коммитов, последний 2026-09-15. **[точно]**
- Состав:
  - `obsidian-markdown`: синтаксис Obsidian (wikilinks, embeds, callouts, properties). **Obsidian не нужен**, это знания о формате.
  - `obsidian-bases`: файлы `.base` (табличные представления, фильтры, формулы). Сами файлы писать
    можно, но **отображаются они только в Obsidian**.
  - `json-canvas`: файлы `.canvas` (открытый формат JSON Canvas). Obsidian не нужен.
  - `obsidian-cli`: «Requires Obsidian to be open», **нужен запущенный Obsidian**, в облаке неприменим.
  - `defuddle`: извлечение чистого markdown из веб-страниц через Defuddle CLI (npm). Полезно как
    замена WebFetch, требует установки CLI.
  - `knap`: рендер markdown-шаблонов из JSON/CSV через Knap CLI.
  **[точно]** (frontmatter SKILL.md)
- В эфемерном облачном контейнере 4 из 6 skills работают без Obsidian, `obsidian-cli` не работает. Для
  Python-проекта ADE они полезны только если сознательно вести базу знаний в формате Obsidian-vault
  (wikilinks, canvas). К экономии токенов на чтении кода отношения не имеют. Косвенная польза только у
  `defuddle` (меньше мусора с веб-страниц). **[вероятно]**

## 4. Окупаемость Graphify для ADE

### 4.1 Модель затрат (оценки, не измерения)
| Статья | Стоимость | Метка |
|---|---|---|
| Сборка графа только по коду | 0 LLM-токенов; секунды или минуты CPU | точно |
| Семантический этап по .md/docs | токены субагентов, пропорционально объёму документов | точно (факт), гипотеза (объём) |
| Вызов `/graphify` (skill в контексте) | ≈11–12k токенов за вызов | точно (размер файла) |
| Блок always-on в CLAUDE.md | ≈300 токенов в каждой сессии | точно (размер файла) |
| Ответ `graphify query` | до ≈2k токенов (бюджет) | точно |
| Типичная ориентация через rg+Read по проекту | 5–30k токенов на вопрос | гипотеза |
| Установка в облаке на каждую сессию | `uv tool install` + около 27 wheel-пакетов, десятки секунд, сеть до PyPI | вероятно |

### 4.2 Порог окупаемости **[гипотеза]**
- Меньше ~50 файлов или ~10k LOC: проект целиком описывается в CLAUDE.md и PROJECT_STATUS.md, а rg
  находит всё за 1–2 вызова. Граф не окупает установку, загрузку skill и накладные расходы hook.
  Авторы сами получили около 1× на 6 файлах.
- 100–300 файлов или 20–50k LOC: польза возможна на вопросах о структуре («кто вызывает X», «путь от
  A к B»). Решать нужно только по замеру (см. 4.4).
- Больше 300 файлов, несколько пакетов, много связей между модулями: вероятная зона пользы, судя по
  ERPNext. Даже там подтверждён прирост качества, а не экономия токенов.

### 4.3 Совместимость с Claude Code Cloud (эфемерный контейнер)
- Граф можно закоммитить (`graphify-out/graph.json` + `.gitattributes`). Минусы: шум в диффах PR,
  мегабайты на крупных репозиториях. Merge driver регистрируется в `.git/config`, а git hooks
  хранятся в `.git/hooks`. **Ни то ни другое не версионируется**, поэтому в каждой новой сессии
  контейнера их пришлось бы ставить заново (SessionStart hook). **[точно]** по устройству git.
- Лучше для эфемерной среды **[вероятно]**: граф не коммитить (`graphify-out/` в .gitignore) и
  пересобирать в SessionStart-hook командой `graphify update .` / `--code-only`. AST детерминирован и
  бесплатен. Тогда граф не устаревает относительно checkout.
- **Риск устаревания**: если граф закоммичен, а hooks не стоят, после каждой правки агентом граф
  отстаёт от кода до следующей сборки. Агент, которого hook подталкивает к графу, будет опираться на
  устаревшие связи. Для активно меняющегося кода ранней стадии этот риск высокий. **[вероятно]**

### 4.4 Как измерить, прежде чем внедрять (протокол)
1. Зафиксировать 5–8 типовых вопросов ориентации («где вычисляется X», «что сломается при изменении Y»).
2. Прогнать их в чистых сессиях: (А) CLAUDE.md + rg/Glob; (Б) то же + `graphify query`, без hook.
3. Сравнить входные токены (usage в логах сессии или `/cost`), число вызовов инструментов и
   корректность ответа (чек-лист фактов). Минимум 2 прогона на вариант.
4. Внедрять, только если (Б) дешевле на ≥30% при не худшей корректности.

## 5. Сравнение с альтернативами

| Подход | Стоимость | Свежесть | Облако | Когда годится |
|---|---|---|---|---|
| CLAUDE.md (≤150 строк) + PROJECT_STATUS.md (≤60 строк) | ≈1–3k токенов на сессию, ручное ведение | ручная, риск устаревания текста | идеально (в git) | всегда, база |
| ripgrep / Glob / Grep (встроены) | платим за то, что прочитали; узкие запросы дешёвые | всегда актуально | идеально | до сотен файлов |
| ctags / tree-sitter repo-map (как в Aider) | сигнатуры с ранжированием, бюджет около 1k токенов; генерируется скриптом за секунды | пересобирается на лету | идеально, без hooks | 50–500 файлов, дёшево сделать самим |
| Встроенная память Claude Code (CLAUDE.md иерархия, auto-memory) | небольшая | ручная или полуавтоматическая | CLAUDE.md в репо работает; пользовательская память вне репо в эфемерном контейнере может не сохраниться | заметки о решениях |
| Graphify (только код) | 0 на сборку, около 12k на skill, около 300 на сессию | только при пересборке | работает при установке в SessionStart | крупные репозитории, вопросы о связях |
| Graphify + docs | плюс токены субагентов | то же | то же | смешанные корпусы (код, статьи, PDF) |

Метки: стоимости в таблице **[гипотеза]**, кроме Graphify (см. 2.2) и бюджета Aider repo-map
(по умолчанию 1k токенов, документация Aider, **[вероятно]**).

Замечание: компактный repo-map можно получить и без Graphify. Достаточно скрипта на 50–100 строк на
`ast` из stdlib Python (модули, классы, функции, импорты), который генерирует `docs/REPO_MAP.md`
командой или в CI. Для чистого Python-проекта это даёт основную часть пользы графа без зависимостей и
hooks. **[гипотеза]**

## 6. Рекомендация

**Сейчас не внедрять Graphify. obsidian-skills не внедрять** (нет потребности в Obsidian-формате;
`defuddle` можно рассмотреть отдельно для веб-ресёрча).

Сейчас:
1. CLAUDE.md (правила, команды, архитектура в 20–40 строках) + PROJECT_STATUS.md (текущее состояние,
   ≤60 строк), обновлять в конце каждой задачи.
2. Навигация через rg/Glob. Правило в CLAUDE.md: «сначала узкий поиск, читать диапазоны строк, а не
   файлы целиком».

Триггеры пересмотра (любой):
- в пакете больше ~150 `.py` файлов или больше ~30k LOC;
- больше 3 подпакетов с перекрёстными зависимостями, и агент регулярно ошибается в связях;
- замер (протокол 4.4) показывает, что больше 30% токенов сессии уходит на ориентацию.
Порядок действий при срабатывании: сначала свой repo-map на `ast` (дёшево, без hooks). Graphify
пробовать только если repo-map не помог: версия зафиксирована, `--code-only`, без `--strict`, без
коммита графа, пересборка в SessionStart, контрольный замер по 4.4.
