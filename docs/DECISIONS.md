## D-001. Память проекта — Markdown в GitHub, без Obsidian (предложено, 2026-10-14)
- Контекст: работа в Claude Code Cloud через браузер; локального Obsidian в контейнере нет. `obsidian-cli` из kepano/obsidian-skills требует запущенного Obsidian ([[research/token-economy]]).
- Решение: `docs/*.md` в репозитории как единственная постоянная память. Формат совместим с Obsidian (папку можно открыть как vault).
- Альтернативы: Obsidian Sync/локальный vault — недоступен в облаке; встроенная память Claude — не версионируется в GitHub.
- Последствия: никакой зависимости от Obsidian; PROJECT_STATUS.md ≤60 строк — точка входа для каждой сессии.

## D-002. Субагенты — файлы `.claude/agents/*.md`, делегирование через Agent tool (предложено)
- Контекст: проверено 2026-10-14 — сразу после создания файлов вызов `subagent_type: qa` дал ошибку «Agent type 'qa' not found»; после регистрации репозитория и следующего хода агенты `researcher/architect/developer/qa` появились и были использованы по имени (developer исправил дефекты spike_01, qa перепроверил). Значит, делегирование реально работает, но новые агенты становятся доступны со следующего хода.
- Решение: держать конфиги в репо и вызывать по имени. Запасной путь, если агенты не загружены: general-purpose агент с инструкцией прочитать файл роли (так проведён первый QA spike_01).

## D-004. Graphify — установлен по решению владельца, используется по триггеру (принято 2026-10-14)
- Контекст: заявленная экономия «71×» = весь корпус против одного ответа графа, не замер работы агента; на малых проектах сами авторы получают ~1×. Skill стоит ~11–12k токенов на вызов. Git hooks не переживают эфемерный контейнер → риск устаревшей карты ([[research/token-economy]]).
- Решение: CLAUDE.md + PROJECT_STATUS.md + rg/Glob с выборочным чтением.
- Триггер пересмотра: >150 .py файлов или >30k строк, или замер показывает >30% токенов сессии на ориентацию в коде. Тогда сначала свой repo-map на `ast`, Graphify — только после контрольного замера до/после, `--code-only`, граф не коммитить.

## D-005. Концепция v0: своя размеченная библиотека слайдов + skill + детерминированная сборка (принято Анной 2026-10-14)
- Контекст: Анна уточнила идею — частые слайды в своей библиотеке, skill выбирает слайд и адаптирует, на выходе редактируемый PPTX. Интервью не будет, срок — несколько дней.
- Решение: библиотека размечается вручную (заметки `ade:` + имена фигур), варианты по числу элементов (cards-2/3/4/5) верстает дизайнер, программа клонирует только при отсутствии варианта. Claude выбирает слайды и раскладывает текст; операции и QA — Python. Мастер-слайды — только для простых слотов (у макета фиксированное число плейсхолдеров).
- Альтернативы: автораспознавание чужих макетов (главный риск, отложено; spike_02 остановлен); всё делать через Claude in PowerPoint (недетерминированно, нет QA).
- Последствия: риск «понять чужой макет» снят; ценность ограничена библиотекой, которую надо поддерживать. Подробно — `docs/ARCHITECTURE.md`.

- Обновление 2026-10-14: Анна настояла на установке. Установлено: `graphifyy==0.9.90`, хук SessionStart `.claude/hooks/graphify-refresh.sh` пересобирает карту без LLM, `graphify-out/` не коммитится, skill Graphify не ставится (экономит ~11–12k токенов на вызов). Замер: `docs/research/graphify-benchmark.md` — на текущем размере карта дороже поиска на ~10%. Правило: для вопросов «что зависит от X / кто вызывает X» в большом коде можно `graphify affected/explain`; по умолчанию — rg.
