# Spike 01 — пять структурных адаптаций PPTX (2026-10-14)

**Вопрос:** реализуемы ли обязательные адаптации из мастер-промпта на python-pptx 1.0.2 + прямом OOXML без потери редактируемости?

**Как воспроизвести:**
```bash
python3 make_template.py /tmp/t.pptx && python3 adapt.py /tmp/t.pptx /tmp/a.pptx && python3 qa.py /tmp/a.pptx
soffice --headless --convert-to pdf /tmp/a.pptx   # визуальный контроль
```
Макет синтетический (`make_template.py`), контент синтетический.

## Результаты

| Операция | Результат | Доказательство |
|---|---|---|
| Карточки 3 → 4 (группы) | Работает: клон группы, равномерное перераспределение в том же пролёте, стиль сохранён | `qa.py`: 4 карточки, нет наложений; `evidence/compare.png` |
| Таблица 5 → 7 строк | Работает: клон `a:tr` через одну строку сохраняет чередование заливки | `qa.py`: заливки `1F2A44,F2F4F7,FFFFFF,…` |
| Диаграмма 3 → 4 категории | Работает: `replace_data` обновляет XML-кэш и встроенный xlsx, цвет серии сохранён | `qa.py`: категории `A–D`, цвет `00A39A` |
| Процесс 4 → 5 этапов | Работает: клоны круга/подписи/коннектора, пересчёт шага и уменьшение диаметра | `qa.py`: 5 этапов, 4 коннектора |
| Длинный текст | Работает: измерение по метрикам шрифта (Pillow), блок растёт, сноска сдвигается, текст не сокращается | вывод `adapt.py`: 14 строк, fits=True; рендер совпал по числу строк |

## Найденные дефекты (важнее успехов)

1. **Разрыв слова при сужении.** «Редактируемость» в карточке и «Масштабирование» в подписи этапа рвутся посередине. Первая версия `qa.py` (только геометрия и структура) дала **PASS** — дефект увидели только на рендере. После добавления метрической проверки «самое длинное слово шире блока» `qa.py` ловит оба случая автоматически.
   *Вывод:* структурный QA необходим, но недостаточен; нужны метрические проверки текста + рендер.
2. Адаптер опирается на **имена фигур** (`Card 1`, `Step 1 circle`). В реальных макетах имена случайны (`Rectangle 17`), часть элементов — плейсхолдеры с наследуемым стилем, SmartArt, сгруппированные иначе. Распознавание «что здесь карточка» — главный нерешённый риск, этот спайк его **не проверял**.
3. Рендер LibreOffice ≠ PowerPoint (метрики шрифтов, автоподгонка). Открытие в настоящем PowerPoint не проверено.

## Чего спайк НЕ доказывает
- Работу на реальных профессиональных макетах (best case: макет сделан мной, с чистой структурой).
- SmartArt, плейсхолдеры, мастер-слайды, связанные диаграммы, think-cell объекты.
- Совместимость с PowerPoint desktop/web (только python-pptx + LibreOffice).

## Исправления
- D1: `adapt.py` — `clone_after()` перенумеровывает все `p:cNvPr id` клона (max id на слайде + 1..) в `adapt_cards` и `adapt_process`. `qa.py` проверяет уникальность `cNvPr id` в каждом `slide*.xml` (FAIL при дублях).
- D2: `adapt.py` — `fit_uniform()`: кегль однотипных элементов (Card title, Card body, Step label) уменьшается шагом 1pt до помещения самого длинного слова (Inter Regular/Bold, Pillow, поля lIns+rIns), не ниже 75% исходного, единый для всех элементов типа; если не влезает — текст не сокращается, в stdout выводится WARNING.
- Проверка: `make_template.py T && adapt.py T A && qa.py A` -> STRUCTURE PASS; рендер soffice: «Редактируемость», «Масштабирование» целы.
